# 手工矩形绕圈 Debug 操作流程

## 目的

这份流程不是解释代码，而是告诉你上车时按什么顺序做、看什么数据、怎么判断问题在哪一层。先把底盘和里程计调通，再回到 BFS 和推箱子。

## 调试前准备

### 1. 确认当前默认模式

检查 `robot_param.h` 中：

```c
#define SMARTCAR_RUNTIME_MODE (SMARTCAR_MODE_MANUAL_RECT_LAP)
```

如果你想先做四轮检查，就临时切成：

```c
#define SMARTCAR_RUNTIME_MODE (SMARTCAR_MODE_WHEEL_SIGN_CHECK)
```

### 2. 确认起点摆放

- 小车摆在场地逻辑起点 `(1, 6)` 对应格子中心。
- 车头朝向默认正前方。
- 开机前尽量把车摆正，不要斜着压线。

### 3. 确认地面条件

- 用比赛地面或尽量接近的平整地面。
- 轮胎表面不要有灰、胶带、毛发。
- 不要在很滑的瓷砖地面直接调里程计。

### 4. 记录方式

建议每次测试都记 4 类信息：

1. 实际运动轨迹
2. 最终停点和目标点差多少
3. 遥测页里显示的 `dx/dy`、`yaw_err`
4. 哪条边最容易出问题

最好用手机从上往下录像，后面回放比肉眼靠谱。

## 第一阶段：四轮正反转映射检查

### 目标

确认三件事：

1. 命令的轮子是不是对的轮子在转
2. 编码器是不是对应了同一个轮子
3. 正向 PWM 后，归一化后的编码器增量是不是正数

### 操作

1. 把模式切成 `SMARTCAR_MODE_WHEEL_SIGN_CHECK`
2. 下载程序上板
3. 悬空或轻扶车体，避免乱跑
4. 观察每一步 BLE 四数输出和实际车轮运动

### 每一步应该怎么判

当前输出定义：

- `a = 当前步骤编号`
- `b = 当前被测轮编码器增量`
- `c = 其他三轮编码器绝对值最大值`
- `d = 当前 PWM`

### 合格标准

#### 对于 `LF+ / RF+ / LB+ / RB+`

- 只有被测轮明显转动
- `b > 0`
- `c` 很小，接近 0

#### 对于 `LF- / RF- / LB- / RB-`

- 只有被测轮明显反向转动
- `b < 0`
- `c` 很小，接近 0

### 如果不合格，怎么判断

#### 情况 A：转的是别的轮

说明电机通道映射错了，优先检查：

- `motor_driver.c`
- `hardware_config.h` 里的 `MOTOR1/2/3/4_DIR/PWM`

#### 情况 B：轮子转对了，但 `b` 符号反了

说明编码器方向归一化错了，优先改：

- `hardware_config.h` 里的 `ENCODER1/2/3/4_FORWARD_SIGN`

#### 情况 C：轮子转对了，但 `c` 很大

说明有两个可能：

1. 编码器映射串了
2. 实际有其他轮跟着拖动，但不应该拖得这么大

优先先查编码器通道对应关系，再查机械拖拽。

### 这一阶段不过，不要进下一阶段

如果四轮正反转都没完全对上，后面的里程计、斜走、提前停判断都会失真。

## 第二阶段：手工矩形绕圈

### 目标

验证 4 件事：

1. 点到点是否沿预期轴向走
2. 里程计尺度是否和真实距离一致
3. 是否因为 yaw hold 干扰而斜走
4. 是否因为完成判据过早而提前停

### 当前固定路线

从 `(1, 6)` 出发，按以下顺序跑：

1. `U4`
2. `R13`
3. `D9`
4. `L13`
5. `U5`

理论上最后回到起点附近。

### 调试时看哪几页

当前遥测会自动轮播这几页。

#### `POSE`

- `a = phase`
- `b = current_segment_index`
- `c = x_mm`
- `d = y_mm`

看它是否在持续变化，是否大体和实际方向一致。

#### `TARGET`

- `a = target_x_mm`
- `b = target_y_mm`
- `c = dx_mm`
- `d = dy_mm`

这是最关键的一页。

如果车停住时 `dx/dy` 还很大，说明不是“已经到点”，而是控制没有再推进。

#### `STATE`

- `a = vx_body_mmps`
- `b = vy_body_mmps`
- `c = yaw_cd`
- `d = yaw_error_cd`

看车在直行时 yaw 误差是不是很大，或者 body 速度是不是明显跑偏。

#### `WHEEL_F`

- `a = LF target`
- `b = LF feedback`
- `c = RF target`
- `d = RF feedback`

#### `WHEEL_R`

- `a = LB target`
- `b = LB feedback`
- `c = RB target`
- `d = RB feedback`

这两页主要看四轮跟踪是否对称。

## 第三阶段：怎么判断“斜着走”

### 现象 1：命令前进，但实际往右前或左前斜着走

优先看 `STATE` 页：

- 如果 `yaw_error_cd` 很小，但实际轨迹斜，优先怀疑：
  - 轮径或编码器比例不一致
  - mecanum 轮组安装角/受力问题
  - 单轮速度环跟踪偏差太大
- 如果 `yaw_error_cd` 持续偏大，优先怀疑：
  - 航向环在持续打补偿
  - IMU 零偏或 yaw 基准有问题

### 对应再看 `WHEEL_F / WHEEL_R`

如果同侧或对角轮经常出现：

- `target` 很大
- `feedback` 明显跟不上

说明不是简单“坐标换算错”，而是某几个轮闭环能力弱。

## 第四阶段：怎么判断“跑得慢”

### 先不要直接怪 PID

先分两类看：

#### 类 A：目标命令本来就小

看 `WHEEL_F / WHEEL_R` 页，如果四轮 `target` 就不高，说明上层给的速度就保守。

这时优先检查：

- `POINT_MOVE_MAX_SPEED_MMPS`
- `POINT_MOVE_NEAR_MAX_SPEED_MMPS`
- `POINT_MOVE_MIN_EFFECTIVE_MMPS`
- 是否已经提前进入 near 区

#### 类 B：目标命令不小，但反馈起不来

如果 `target` 明显有值，而 `feedback` 长期偏小，才更像是：

- 速度环参数问题
- PWM 输出受限
- 摩擦太大
- 某轮机械阻力异常

## 第五阶段：怎么判断“距离不对”

### 先区分是统一比例偏差，还是 X/Y 不同

#### 情况 A：前后、左右都按比例偏短或偏长

优先怀疑：

- `PULSE_PER_MM`

#### 情况 B：X 比例和 Y 比例不同

优先怀疑：

- `ODOM_SCALE_X`
- `ODOM_SCALE_Y`

### 具体做法

1. 让车只跑单段直线
2. 实际量真实位移
3. 记下遥测里的 `x_mm/y_mm` 变化
4. 计算比例

建议至少测：

1. 前进 `400 mm`
2. 前进 `800 mm`
3. 右移 `400 mm`
4. 右移 `800 mm`

### 判断规则

#### 如果前进和右移都偏同一比例

先调 `PULSE_PER_MM`

#### 如果前进差不多，但横移误差大

先调 `ODOM_SCALE_X`

#### 如果横移差不多，但前进误差大

先调 `ODOM_SCALE_Y`

## 第六阶段：怎么判断“离目标一两格就停住”

这是你现在最要重点盯的现象。

### 先看 `TARGET` 页

如果车停住时：

- `dx/dy` 已经很小，接近 0

那说明它认为自己到了，问题可能在里程计本身。

如果车停住时：

- `dx/dy` 仍然很大

那说明它不是“算到点了”，而是“控制推不动了”。

### 再分两种

#### 情况 A：`dx/dy` 还大，但四轮 `target` 也几乎归零

这更像上层过早认为完成，优先查：

- `EXEC_SEGMENT_ACCEPT_TOL_MM`
- `POINT_MOVE_FINISH_TOL_MM`

这次手工模式已经把两者都收紧到 `20 mm`，如果仍提前停，就不是单纯阈值松的问题。

#### 情况 B：`dx/dy` 还大，四轮 `target` 也还有，但车不动

更像：

- 低速段命令不足以克服静摩擦
- 速度环输出打不上去
- 某个轮掉速严重

这时重点看：

- `POINT_MOVE_NEAR_MAX_SPEED_MMPS`
- `POINT_MOVE_MIN_EFFECTIVE_MMPS`
- 四轮 `target/feedback`

## 第七阶段：建议的实测顺序

每次只改一类参数，改完立刻复测，不要一口气改很多。

### 建议顺序

1. 四轮映射检查
2. 手工矩形绕圈，先只观察不改参数
3. 单段前进/右移量距
4. 校 `PULSE_PER_MM` 或 `ODOM_SCALE_X/Y`
5. 再跑矩形
6. 如果还提前停，再调完成阈值和 near 区速度
7. 最后才动 `speed_pid` / `angle_pid`

## 第八阶段：每次改参数后如何复测

### 改尺度参数后

复测：

1. 单段前进
2. 单段右移
3. 一圈矩形闭环

### 改完成判据后

复测：

1. 单段短距离 `400 mm`
2. 观察车是否还会提前停
3. 停下时看 `dx/dy`

### 改速度环或航向环后

复测：

1. 单段直线
2. 单段横移
3. 一圈矩形
4. 看是否出现新振荡

## 第九阶段：建议记录模板

每次测试建议按下面格式记：

```text
日期/时间：
当前模式：
地面：
电池状态：

本次只改了：
- 参数1
- 参数2

测试项目：
- 轮映射检查 / 前进400 / 右移800 / 手工矩形

现象：
- 是否斜走
- 是否提前停
- 是否闭环回到起点

遥测结论：
- TARGET页：
- STATE页：
- WHEEL_F页：
- WHEEL_R页：

下一步判断：
- 先改尺度 / 先改完成判据 / 先改速度环 / 先查机械
```

## 最后建议

### 一定不要同时做这几件事

不要在同一轮里同时：

1. 改里程计比例
2. 改完成判据
3. 改 speed PID
4. 改 angle PID

否则跑完你也不知道是哪一个起作用。

### 当前最推荐的现场顺序

1. 先切 `WHEEL_SIGN_CHECK`
2. 轮向、编码器全对后切回 `MANUAL_RECT_LAP`
3. 先看一圈的 `TARGET` 页和 `WHEEL_F/WHEEL_R` 页
4. 如果误差像比例问题，先调尺度
5. 如果误差像“快到点推不动”，先调 near 区速度和完成判据
6. 最后再碰 PID
